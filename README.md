# Group Trip OS booking automation core

Branch: `group-trip-os-2026-10-10`

This branch contains the deterministic core for the approved booking flow:

1. Quote issued
2. Inventory rechecked
3. Square payment link created
4. Payment confirmed for the quoted amount while the inventory check is still valid
5. Reservation confirmed
6. Monthly rental only: GMO Sign contract sent
7. Monthly rental only: GMO Sign contract signed

## Safety / operating rules

- 100% advance payment only. The previous 30/70 split is not implemented.
- Payment amount mismatch never confirms a reservation automatically.
- If the inventory confirmation has expired before payment confirmation, the flow goes to `MANUAL_REVIEW` instead of confirming the reservation.
- Short stays never enter the GMO Sign contract path.
- External calls must use the deterministic idempotency keys generated by `idempotencyKey()`.
- No Square, OTA, AirHost, Lodgify, or GMO Sign credentials are stored in this branch.
- This is the core state machine. Provider adapters and live credentials are the next integration layer.

## Files

- `src/booking-flow.ts`: state machine, guards, next action, idempotency keys
- `tests/booking-flow.test.ts`: normal short-stay flow, monthly GMO flow, amount mismatch, expired inventory, wrong contract path

The provider-specific integration must preserve this order: inventory recheck -> payment confirmation -> reservation confirmation. Monthly contracts are sent only after reservation confirmation, per the current project rule.
