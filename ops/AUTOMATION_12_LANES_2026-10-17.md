# ①②③④ × 3戦略 — 12レーン自動実行仕様（2026-10-17）

## 目的
期限内達成ではなく「期限前達成」を標準とする。4事業軸 × 3独立戦略 = 最低12レーンを同時並行で動かし、1レーン停止時も全体を止めない。

## 固定戦略
- A: 直接営業
- B: 提携・紹介・販売チャネル
- C: 市場側からの問い合わせ獲得

## 12レーン
1A GuestOps AI低単価: 高適合宿泊事業者への個別営業
1B GuestOps AI低単価: 宿泊運営/PMS/スマートロック/清掃・運営支援等との提携
1C GuestOps AI低単価: 商品ページ・サンプル請求・診断導線
2A GuestOps AI継続/上位: 既存購入者・高課題企業への上位提案
2B GuestOps AI継続/上位: IT導入支援/宿泊DX企業等との提携
2C GuestOps AI継続/上位: 無料診断・導入相談・補助制度入口
3A AI検証所/判断負債: AI/DX企業への個社診断型営業
3B AI検証所/判断負債: AI導入/DX/コンサル企業との提携
3C AI検証所/判断負債: 診断・企業サイト・問い合わせ導線
4A Group Trip OS: 法人・旅行需要への直接開拓
4B Group Trip OS: 旅行・宿泊・不動産関連との提携
4C Group Trip OS: OTA・自社導線・紹介流入

## 自動化対象
- 候補企業/提携先の収集
- 既存除外・重複・営業禁止・適合性チェック
- ICPスコアリング
- 個社別の課題仮説と損失回避メッセージ生成
- 低摩擦CTA付き営業文面の下書き生成
- 返信/不達/商談/受注/売上/利益のステータス分類
- 次アクション判定
- 強いレーンへの資源再配分提案
- ページ/導線/FAQ/診断の改善案生成
- GitHub Issue/PR上の実行キュー更新

## 承認を残す操作
外部への不可逆な送信・公開・契約変更・価格変更・削除は、既存の承認ルールとAGENTS.mdに従う。虚偽の実績、根拠のない数値、虚偽の希少性、無差別送信、大量自動DMは行わない。

## 前倒し運用
- 期限から逆算して均等配分しない。
- 最短着手 → 最短検証 → 勝ち筋へ即増量。
- 反応の弱い施策は早期に差し替える。
- 目標100に対し、レーン合計120〜150程度の能力を持たせる。
- 目標達成後は残余期間を上振れ・未達補正・翌月前倒しに使う。

## KPI
母数 / 到達 / 返信 / サンプル希望 / 商談 / 成約 / 売上 / 利益を分離して記録。
送信数や作業量を成果とみなさない。

## 障害時の切替
Aが止まる → B/Cへ即切替。
Bが止まる → A/Cへ即切替。
Cが止まる → A/Bへ即切替。
「復旧待ち」を作業として扱わない。

## Codex実行原則
1. AGENTS.mdを最優先で遵守。
2. 既存Square商品/URL/価格/GAS構成を無断変更しない。
3. 既存の実データと公開情報を使い、推測を事実として記録しない。
4. 1回の実行で「計画」だけを残さず、可能な実装・更新・検証まで進める。
5. ブロッカーがある場合は、止まらず別レーンの次タスクへ移る。
6. 変更はPRで可視化し、CIを通す。
